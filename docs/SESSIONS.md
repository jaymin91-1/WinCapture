# WinCapture 세션 계획

각 세션은 순서대로 진행한다. 이전 세션이 사용자 승인을 받기 전에는 다음 세션을 시작하지 않는다.
세션 안의 세부 작업 분할은 QA 에이전트가 담당한다.
에이전트는 맥에서 일하므로 앱을 실행할 수 없다. SPEC의 [수동] 기준은 세션이 끝날 때 사용자가 Windows PC에서 확인한다.

## 공통 완료 기준 (모든 세션에 적용)
1. 맥에서 `dotnet test tests/WinCapture.Core.Tests`가 모두 통과한다.
2. 맥에서 `dotnet build WinCapture.sln`이 오류 없이 끝난다. (맥에서 WPF 빌드가 도구 문제로 안 되면 보고서에 적고, 3번을 기준으로 한다)
3. 최신 커밋에 대한 GitHub Actions(windows-latest) build + test가 성공한다.
4. 이전 세션까지의 테스트가 모두 그대로 통과한다.
5. 테스트를 삭제하거나, 건너뛰거나, 기대값을 바꿔서 통과시키지 않았다.
6. 이번 세션 범위의 SPEC [자동] 기준은 모두 테스트로 존재하고, [정적] 기준은 qa 리뷰에 근거(파일, 호출 위치)가 적혀 있다.
7. 새로 생긴 경고가 없다. TECH-RULES.md의 규칙을 어기지 않았다.
8. PROGRESS.md에 세션 결과가 기록되고, 모든 변경이 커밋·푸시되어 있다.
9. 세션 종료 보고에 이번 세션의 [수동] 기준이 "사용자 확인 항목"으로 빠짐없이 나열되어 있다.

## Windows PC 확인 방법 (사용자, 매 세션 종료 후)
```powershell
git pull            # 처음에는 git clone
dotnet build WinCapture.sln -c Debug
dotnet test
dotnet run --project src/WinCapture.App
```
확인 결과는 폰에서 진행자에게 "세션 N 승인" 또는 "수정 요청: ..."으로 알린다.

## 세션 1: 골격과 CI
**목표**: 솔루션 뼈대와 Windows CI를 갖추고, Windows PC에서 트레이 앱이 뜨고 꺼지는 것을 확인한다.

**포함 범위**
- 솔루션과 4개 프로젝트 생성 (TECH-RULES.md 구조), `EnableWindowsTargeting`, Nullable
- DI(Generic Host), Serilog 파일 로그
- F-01 앱 상주와 단일 인스턴스, 트레이 메뉴 골격(항목은 표시만, 미구현 항목은 비활성)
- F-02 설정 저장
- 빈 설정 창(WPF-UI, 탭 6개 껍데기)
- `.github/workflows/ci.yml` (windows-latest, push/PR 시 build + test)
- `.gitignore`(.NET), MIT `LICENSE`, README 초안

**권장 작업 순서**
1. 솔루션·프로젝트·CI → 2. Core 설정 모델과 테스트 → 3. App 호스트·트레이·단일 인스턴스 → 4. 설정 창 껍데기·README

**세션 완료 기준**
- F-01 [정적][CI], F-02 [자동] 전부

**사용자 확인 항목**
- F-01 [수동] 1, 2
- 설정 창 분위기(Mica, 다크/라이트)

## 세션 2: 영역 지정, 테두리, 이동/리사이즈, 앱 창 토글
**목표**: 핵심 요구사항인 "결과물에 안 찍히는 빨간 테두리"를 Windows에서 눈으로 확인한다.

**포함 범위**
- F-03 전역 단축키 (모델, 파싱, 충돌 검사, RegisterHotKey 서비스. 설정 UI는 세션 6)
- F-04 영역 지정, F-05 좌표와 DPI
- F-06 테두리 오버레이와 캡처 제외 (`OverlayWindowBase`)
- F-07 영역 이동과 크기 조절
- F-08 앱 창 숨김/표시

**권장 작업 순서**
1. Core: 단축키 모델, 좌표 변환, 사각형 정규화, 히트 테스트, 이동/리사이즈 제한, 겹침 판정 (모두 단위 테스트) → 2. Native: P/Invoke 래퍼 → 3. OverlayWindowBase와 테두리 → 4. 선택 오버레이 → 5. 이동/리사이즈 → 6. 단축키 서비스 연결과 앱 창 토글

**세션 완료 기준**
- F-03, F-04, F-05, F-06, F-07, F-08의 [자동] [정적] 기준 전부

**사용자 확인 항목**
- F-03 [수동] 5, F-04 [수동] 1–2, F-05 [수동] 5, F-06 [수동] 4–6, F-07 [수동] 5, F-08 [수동] 2
- 특히 F-06-4: 테두리를 띄운 채 Win+Shift+S로 찍어서 테두리가 안 나오는지

## 세션 4: FFmpeg와 MP4 녹화
**목표**: 영역을 MP4로 녹화하고 정상 재생되는 파일을 얻는다.

**시작 전 사용자 준비**
- Windows PC에 FFmpeg 설치: `winget install Gyan.FFmpeg`

**포함 범위**
- F-10 FFmpeg 탐지
- F-11 MP4 녹화 (인자 빌더, 소스 선택, 하드웨어 인코더 감지, 녹화 상태 표시, 타이머 알약, 녹화 중 영역 잠금 연결)

**권장 작업 순서**
1. Core: 버전 파싱, 탐색 순서, 짝수 보정, 인자 빌더, 소스·인코더 선택 (단위 테스트) → 2. 프로세스 관리(시작, stdin `q` 정지, 타임아웃) → 3. 녹화 상태 UI

**세션 완료 기준**
- F-10, F-11의 [자동] [정적] 기준 전부

**사용자 확인 항목**
- F-10 [수동] 3, F-11 [수동] 7–8, F-07 [수동] 6
