# WinCapture 요구사항 명세서

> 작성 요령 (하네스 공통)
> - 모든 기능에 ID(F-01…)와 **판정 가능한 완료 기준**을 단다.
> - 완료 기준 태그:
>   - **[자동]**: xUnit 테스트로 판정한다. 맥에서 `dotnet test`로 실행되어야 한다.
>   - **[CI]**: GitHub Actions(windows-latest)의 build/test 성공으로 판정한다.
>   - **[정적]**: qa가 코드를 읽어서 판정한다(어느 파일, 어느 호출인지 리뷰에 적는다).
>   - **[수동]**: 맥에서 판정할 수 없다. qa는 반려 사유로 삼지 않고, 세션 종료 보고의 "사용자 확인 항목"으로 넘긴다.
> - 정하지 못한 것은 10장에 적는다. 에이전트는 임의로 정하지 않고 묻는다.
> - 기술 규칙은 `docs/TECH-RULES.md`를 따른다.

## 1. 개요
개발자 본인이 Windows PC에서 쓰는 트레이 상주형 화면 캡처 도구다. 한 번 지정한 영역을 빨간 테두리로 계속 보여주고, 전역 단축키로 그 영역의 스크린샷(PNG), 동영상(MP4), GIF를 지정 폴더에 저장한다. 테두리와 앱 UI는 결과물에 절대 찍히지 않아야 한다. 소스는 GitHub 공개 저장소(MIT)로 관리한다.

## 2. 기술 스택 (변경 금지)
- .NET 10 (LTS), C#, WPF
- Core: `net10.0` / App, Native: `net10.0-windows` (`EnableWindowsTargeting=true`)
- UI: WPF-UI (lepoco/wpfui), 트레이: H.NotifyIcon.Wpf, MVVM: CommunityToolkit.Mvvm
- DI: Microsoft.Extensions.Hosting, 로깅: Serilog (파일)
- 테스트: xUnit + FluentAssertions (Core.Tests)
- 인코딩: FFmpeg 6.0 이상 외부 프로세스 (저장소에 포함하지 않음)
- CI: GitHub Actions `windows-latest`
- 대상 OS: Windows 10 2004 이상 / Windows 11, x64
- 서버, 포트, DB 없음.
- 새 라이브러리 추가가 필요하면 작업 보고서에 이유를 명시한다.

## 3. 디자인 원칙
- 심플한 흰색/파랑 스타일 (2026-11-27 사용자 승인 목업: `docs/design/mockup/`)
  - 배경은 단색(Mica 사용 안 함). 시스템 라이트/다크 테마는 자동 추종한다. 강조색은 시스템 강조색이 아니라 앱 고유 파랑을 쓴다.
  - 라이트: 창 바탕 `#F2F4F6`, 카드·사이드바·제목 표시줄 `#FFFFFF`, 테두리 `#E5E8EB`, 본문 `#191F28`, 보조 `#6B7684`, 강조 `#2F7CF6`(선택 탭 바탕 `#E8F3FF`, 글자 `#1B64DA`)
  - 다크: 창 바탕 `#17171C`, 사이드바·제목 표시줄 `#101013`, 카드 `#202027`, 테두리 `#2C2C35`, 본문 `#F9FAFB`, 보조 `#A0A7B1`, 강조 `#4D8EF7`, 경고 `#FF7A85`
  - 설정은 카드 묶음 + 행(제목, 설명, 오른쪽 컨트롤) 형태. 켜고 끄는 값은 토글 스위치. 카드 모서리 12px, 컨트롤 8px.
  - 제목은 굵은 Segoe UI(세리프 사용 안 함). 단축키는 키캡 모양으로 표시.
  - 트레이 메뉴도 같은 팔레트를 쓰고 항목 옆에 단축키를 표시한다.
  - 트레이 아이콘: 강조 파랑(`#2F7CF6`) 둥근 사각형 안에 흰 점. 앱이 직접 그린 원본 이미지로 한다.
  - 설정 창 탭 아이콘: 목업(`docs/design/mockup/`)과 같은 얇은 선 아이콘(선 두께 약 1.6, 18px). 일반=톱니, 단축키=키보드, 캡처=모서리 괄호, 녹화=비디오 카메라, FFmpeg=렌치, 정보=원 안의 i
- 글꼴: 시스템 기본(Segoe UI Variable). 별도 폰트를 번들하지 않는다.
- 캡처 테두리: 기본 빨강 `#FF3B30`, 두께 2px, 영역 **바깥쪽**에 그린다.
- 리사이즈 그립: 영역 우하단 바깥에 12×12px, 테두리와 같은 색의 삼각형 표시
- 영역 선택 오버레이: 검정 40% 딤, 선택부는 원본 밝기, 크기 라벨(`800 × 600`)
- 녹화 표시: 테두리 1초 주기 점멸 + 영역 바깥 상단 중앙의 타이머 알약(`● REC 00:12`)
- 금지: 다른 캡처 프로그램(ShareX, Snagit, Windows 캡처 도구 등)의 로고, 이름, 아이콘 사용

## 4. 화면 구성
| 화면 | 설명 |
|---|---|
| 트레이 아이콘 + 메뉴 | 앱의 기본 진입점. 상주 중 항상 표시 |
| 설정 창 | 좌측 내비게이션 탭: 일반 / 단축키 / 캡처 / 녹화 / FFmpeg / 정보 |
| 영역 선택 오버레이 | 전체 가상 화면을 덮는 딤 창, 드래그로 영역 지정 |
| 테두리 오버레이 | 지정 영역 바깥의 빨간 테두리 + 우하단 그립 |
| 녹화 타이머 알약 | 녹화 중에만 표시 |
| 첫 실행 안내 | FFmpeg 탐지 결과 + 기본 단축키 안내 (한 화면) |
| 토스트 알림 | 저장 완료, 변환 진행/완료, 오류 |

트레이 메뉴 항목 순서: 영역 지정 / 스크린샷 / 동영상 녹화 시작·정지 / GIF 녹화 시작·정지 / 창 표시·숨김 / 저장 폴더 열기 / 설정 / 종료

## 5. 기능 요구사항

### F-01 앱 상주와 단일 인스턴스 (필수)
- 완료 기준
  1. [수동] 실행하면 트레이 아이콘이 나타나고, 메뉴의 "종료"로 프로세스가 끝난다.
  2. [수동] 두 번째로 실행하면 새 인스턴스가 뜨지 않고 기존 인스턴스의 설정 창이 앞으로 나온다.
  3. [정적] 단일 인스턴스는 이름 있는 Mutex로 구현되어 있다.
  4. [CI] 솔루션 build와 test가 windows-latest에서 성공한다.

### F-02 설정 저장 (필수)
설정 파일은 `%AppData%\WinCapture\settings.json`이다(7장 구조).
- 완료 기준
  1. [자동] 기본 설정을 저장한 뒤 다시 읽으면 모든 값이 같다(왕복 동일).
  2. [자동] 깨진 JSON(`{"saveFolder":`)을 읽으면 예외 없이 기본값을 반환하고, 원본을 `settings.json.bak-yyyyMMddHHmmss`로 남긴다.
  3. [자동] 7장에 없는 키가 들어 있어도 읽기에 실패하지 않는다(무시).
  4. [자동] 설정 파일 경로는 주입 가능하다(테스트는 임시 폴더를 쓴다).

### F-03 전역 단축키 (필수)
| 동작 ID | 동작 | 기본값 |
|---|---|---|
| SelectRegion | 영역 지정 시작 | Ctrl+Alt+R |
| Screenshot | 스크린샷 저장 | Ctrl+Alt+S |
| RecordVideo | MP4 녹화 시작/정지 | Ctrl+Alt+V |
| RecordGif | GIF 녹화 시작/정지 | Ctrl+Alt+G |
| ToggleBorder | 테두리 표시/숨김 | Ctrl+Alt+H |
| ClearRegion | 영역 해제 | Ctrl+Alt+X |
| ToggleAppWindow | 앱 창 숨김/표시 | Ctrl+Alt+W |

- 조합 규칙: 수정자(Ctrl/Alt/Shift/Win) 1개 이상 + 일반 키 1개(A–Z, 0–9, F1–F24). `RegisterHotKey`만 사용한다.
- 완료 기준
  1. [자동] 문자열 `"Ctrl+Alt+R"`을 파싱하면 수정자 {Ctrl, Alt}, 키 R이 되고, 다시 문자열로 바꾸면 `"Ctrl+Alt+R"`이 된다. 수정자 순서는 항상 Ctrl, Alt, Shift, Win이다(`"Alt+Ctrl+R"` 입력 → `"Ctrl+Alt+R"` 출력).
  2. [자동] 수정자가 없는 `"R"`, 일반 키가 없는 `"Ctrl+Alt"`, 일반 키가 두 개인 `"Ctrl+A+B"`는 유효하지 않다고 판정한다.
  3. [자동] 두 동작에 같은 조합을 지정하면 충돌 검사가 두 동작 ID를 모두 반환한다.
  4. [자동] 기본값 7개는 서로 충돌하지 않는다.
  5. [수동] 다른 앱이 이미 등록한 조합이면 등록 실패 토스트가 뜨고, 설정의 단축키 탭에서 해당 항목에 경고 표시가 나온다.

### F-04 영역 지정 (필수)
- 완료 기준
  1. [수동] SelectRegion 단축키를 누르면 모든 모니터를 덮는 딤 오버레이가 뜨고, 드래그한 사각형이 원본 밝기로 보이며 크기 라벨이 표시된다.
  2. [수동] `Esc`를 누르면 취소되고 이전 영역이 그대로 유지된다.
  3. [자동] 드래그 시작점과 끝점이 어느 방향이든(우하→좌상 포함) 정규화된 사각형이 나온다. 예: (500,400)→(100,100) 이면 X=100, Y=100, W=400, H=300.
  4. [자동] 32px보다 작은 드래그(W 또는 H < 32)는 영역으로 인정하지 않는다(선택 취소와 같음).
  5. [자동] 마지막 영역 복원 옵션이 켜져 있으면 영역이 설정에 저장되고 다시 읽힌다.

### F-05 좌표와 DPI (필수)
내부 좌표는 물리 픽셀(가상 화면 좌표)로 통일한다. 반올림은 `MidpointRounding.AwayFromZero`이다.
- 완료 기준
  1. [자동] 배율 150%에서 DIP 사각형 (100, 100, 400, 300)은 물리 픽셀 (150, 150, 600, 450)이다. 역변환도 성립한다.
  2. [자동] 배율 125%에서 DIP (101, 101, 401, 301)은 물리 픽셀 (126, 126, 501, 376)이다.
  3. [자동] 음수 좌표를 지원한다. 배율 100%, DIP (-1920, 0, 800, 600) → 물리 (-1920, 0, 800, 600).
  4. [정적] App 매니페스트에 Per-Monitor V2 DPI 인식이 선언되어 있다.
  5. [수동] 100%와 150% 모니터에서 테두리가 선택한 영역과 픽셀 단위로 맞는다.

### F-06 빨간 테두리 오버레이와 캡처 제외 (필수, 최우선)
- 완료 기준
  1. [정적] 모든 오버레이 창(선택 오버레이, 테두리, 타이머 알약, 드래그 툴팁)이 `OverlayWindowBase`를 상속하고, 이 클래스가 창 핸들 생성 직후 `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)`를 호출한다. 호출이 실패하면 로그를 남긴다.
  2. [정적] 오버레이 창 확장 스타일에 `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`가 있고 Topmost이다.
  3. [자동] 테두리 바깥 사각형 계산: 영역 (100, 100, 400, 300), 두께 2px → 테두리 창 사각형 (98, 98, 404, 304). 테두리는 영역 안쪽 픽셀을 한 개도 덮지 않는다.
  4. [수동] 테두리가 보이는 상태에서 Win+Shift+S로 화면을 찍어도 테두리가 나오지 않는다.
  5. [수동] 영역 안쪽을 클릭하면 아래 앱이 클릭되고, 테두리 창이 포커스를 가져가지 않는다.
  6. [수동] ToggleBorder로 테두리가 숨겨지고 다시 나타난다. ClearRegion으로 영역과 테두리가 사라진다.

### F-07 영역 이동과 크기 조절 (필수)
- 테두리 띠(히트 영역: 영역 바깥 8px)를 드래그하면 이동한다. 우하단 그립(12×12px)을 드래그하면 크기가 바뀌고 좌상단은 고정된다.
- 그립 영역은 영역 우하단 꼭짓점에서 오른쪽·아래로 12px이며, 테두리 띠와 겹치는 부분은 그립이 우선한다.
- 영역 내부는 클릭 통과를 유지한다(`WM_NCHITTEST`에서 `HTTRANSPARENT`).
- 완료 기준
  1. [자동] 히트 테스트: 영역 (100, 100, 400, 300)일 때 점 (300, 250)은 "통과", (95, 200)은 "이동", (502, 402)는 "리사이즈", (80, 80)은 "영역 밖"이다.
  2. [자동] 이동 제한: 가상 화면이 (-1920, 0, 3840, 1080)이고 영역이 400×300일 때, X=1700으로 옮기면 X=1520으로 제한된다(오른쪽 끝 1920 - 400). Y=-50으로 옮기면 Y=0이다.
  3. [자동] 리사이즈 최소 크기: 10×10으로 줄이면 32×32가 된다. 가상 화면 밖으로 늘리면 경계에서 멈춘다.
  4. [자동] 녹화 중 잠금: 잠금 상태에서는 이동/리사이즈 계산 결과가 원래 영역과 같다.
  5. [수동] 테두리 위에서는 이동 커서, 그립 위에서는 ↘ 커서가 나온다. 드래그 중 `X, Y, W × H` 툴팁이 보인다.
  6. [수동] 녹화 중에 드래그하면 "녹화 중에는 영역을 변경할 수 없습니다" 툴팁이 뜨고 영역이 바뀌지 않는다.

### F-08 앱 창 숨김/표시 (필수)
- 완료 기준
  1. [자동] 겹침 판정: 창 (0, 0, 500, 500)과 영역 (400, 400, 200, 200)은 겹친다. 창 (0, 0, 300, 300)과 영역 (400, 400, 200, 200)은 겹치지 않는다. 변이 맞닿기만 하는 경우(창 (0, 0, 400, 400))는 겹치지 않는다.
  2. [수동] ToggleAppWindow 단축키와 트레이 "창 표시/숨김"으로 설정 창이 숨겨지고 다시 나타난다. 트레이 아이콘과 테두리는 그대로 있다.
  3. [수동] "캡처/녹화 시작 시 앱 창 자동 숨김"이 켜져 있으면, 설정 창이 영역과 겹친 상태에서 스크린샷을 찍어도 설정 창이 결과물에 나오지 않는다.

### F-09 스크린샷 (필수)
- 완료 기준
  1. [자동] 파일명: 패턴 `WinCapture_{date}_{time}`, 시각 2026-11-27 09:30:05, 유형 png → `WinCapture_20261127_093005.png`
  2. [자동] 같은 이름이 있으면 `_1`, `_2` 순으로 붙는다. 토큰 `{w}`, `{h}`, `{type}`, `{counter}`가 치환된다. 파일명에 쓸 수 없는 문자(`\ / : * ? " < > |`)는 `_`로 바뀐다.
  3. [자동] 저장 경로: 유형별 하위 폴더 옵션이 켜지면 `<저장폴더>\Screenshots\파일명`, 꺼지면 `<저장폴더>\파일명`.
  4. [수동] 400×300 영역을 찍으면 PNG가 정확히 400×300이고 테두리가 없다.
  5. [수동] 저장 토스트를 클릭하면 탐색기가 열리고 파일이 선택되어 있다.
  6. [수동] 클립보드 복사 옵션이 켜져 있으면 이미지가 클립보드에도 들어간다.

### F-10 FFmpeg 탐지 (필수)
- 완료 기준
  1. [자동] 탐색 순서: 설정값 경로 → 앱 폴더 `ffmpeg\ffmpeg.exe` → PATH. 앞 순서에서 찾으면 뒤는 보지 않는다(파일 존재 확인을 주입 가능하게 해서 테스트).
  2. [자동] `ffmpeg -version` 첫 줄 `ffmpeg version 7.1.1-full_build-www.gyan.dev ...`에서 버전 7.1.1을 읽는다. 6.0 미만이면 "지원하지 않는 버전"으로 판정한다.
  3. [수동] FFmpeg가 없으면 녹화 단축키를 눌렀을 때 설치 안내 토스트가 뜨고, 설정의 FFmpeg 탭에 "찾을 수 없음"이 표시된다.

### F-11 MP4 녹화 (필수)
- 소스: 기본 `ddagrab`. 영역이 두 모니터 이상에 걸치거나 ddagrab을 쓸 수 없으면 `gdigrab`.
- 프리셋: 표준(H.264, 기본) / 고압축(HEVC). 하드웨어 인코더(h264_nvenc, h264_qsv, h264_amf) 감지 시 우선 사용.
- 완료 기준
  1. [자동] 짝수 보정: 801×601 → 800×600, 800×600 → 800×600 (내림).
  2. [자동] gdigrab + 소프트웨어 인코더, 영역 (100, 200, 800, 600), 30fps, 커서 포함, 출력 `out.mp4`의 인자 목록이 정확히 다음과 같다:
     `-y -f gdigrab -framerate 30 -offset_x 100 -offset_y 200 -video_size 800x600 -draw_mouse 1 -i desktop -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p out.mp4`
  3. [자동] ddagrab 인자: 모니터 1번(좌상단 1920, 0)의 영역 (2020, 100, 640, 480)은 `output_idx=1`, `offset_x=100`, `offset_y=100`(모니터 기준 좌표), `video_size=640x480`, `framerate=30`이 들어간 `-f lavfi -i ddagrab=...` 인자가 된다. 소프트웨어 인코더일 때는 `-vf hwdownload,format=bgra`가 추가된다.
  4. [자동] 소스 선택: 영역이 모니터 하나 안에 있으면 ddagrab, 두 모니터에 걸치면 gdigrab.
  5. [자동] 하드웨어 인코더 선택: `ffmpeg -encoders` 출력에 `h264_nvenc`가 있으면 표준 프리셋 코덱은 `h264_nvenc`이고 `-cq 23`을 쓴다. 없으면 libx264.
  6. [정적] 녹화 정지는 FFmpeg stdin에 `q`를 쓰고 종료를 최대 10초 기다린다. 10초가 지나면 강제 종료하고 오류 토스트를 띄운다.
  7. [수동] 10초 녹화한 파일이 Windows 기본 플레이어에서 재생되고, 테두리와 타이머 알약이 영상에 없다.
  8. [수동] 녹화 중 트레이 아이콘이 녹화 상태로 바뀌고, 테두리가 점멸하며 타이머가 흐른다.

### F-12 GIF 녹화 (필수)
- 1단계 임시 MP4 녹화(F-11과 같은 소스, CRF 18) → 2단계 palettegen/paletteuse 변환 → 임시 파일 삭제
- 완료 기준
  1. [자동] 변환 인자: fps 12, 최대 폭 800, 입력 `tmp.mp4`, 출력 `out.gif`일 때 필터 그래프가 정확히
     `fps=12,scale='min(800,iw)':-2:flags=lanczos,split[a][b];[a]palettegen=stats_mode=diff[p];[b][p]paletteuse=dither=bayer:bayer_scale=5:diff_mode=rectangle` 이다.
  2. [자동] 최대 폭이 0(원본)이면 scale 단계가 빠진다.
  3. [수동] 변환 중 토스트로 진행 상태가 보이고, 완료 후 GIF가 브라우저에서 재생되며 임시 MP4가 남지 않는다.

### F-13 설정 화면 (필수)
- 완료 기준
  1. [자동] 설정 ViewModel에서 단축키를 바꾸고 저장하면 단축키 서비스의 재등록 메서드가 한 번 호출된다(서비스는 인터페이스로 주입해 가짜로 검증).
  2. [자동] "기본값 복원"을 누르면 단축키 7개가 F-03 표의 기본값으로 돌아간다.
  3. [수동] 단축키 탭에서 항목을 누르고 키 조합을 누르면 기록되고, 저장 즉시 재시작 없이 새 단축키가 동작한다.
  4. [수동] 시스템 테마를 다크로 바꾸면 설정 창도 다크로 바뀐다.
  5. [수동] 첫 실행 시 안내 화면이 한 번 나오고, 다음 실행부터는 나오지 않는다.

### F-14 저장소와 배포 (필수)
- 완료 기준
  1. [정적] README에 기능 소개, 빌드 방법, FFmpeg 별도 설치 안내(`winget install Gyan.FFmpeg`), 기본 단축키 표, 라이선스가 있다.
  2. [정적] MIT `LICENSE` 파일이 있다. `.gitignore`가 bin/, obj/, publish/, ffmpeg/, *.mp4, *.gif와 테스트 리소스를 제외한 *.png를 제외한다.
  3. [CI] `v*` 태그를 push하면 Actions가 `win-x64` framework-dependent publish 결과를 zip으로 만들어 GitHub Release에 올린다.

## 6. 비기능 요구사항
- 대기 상태 메모리 100MB 이하, CPU는 거의 0% [수동]
- 스크린샷 단축키 입력 후 200ms 안에 저장을 시작한다 [수동]
- 1080p 영역 30fps 녹화에서 체감 프레임 드랍이 없다(하드웨어 인코더 기준) [수동]
- 로그: `%LocalAppData%\WinCapture\logs`, 7일 보관
- 캡처/인코딩은 백그라운드에서 수행하고 UI를 멈추지 않는다.
