# task-05: 영역 선택 오버레이와 영역 상태 저장/복원 (F-04)
## 목표
전체 가상 화면을 덮는 딤 오버레이에서 드래그로 영역을 지정하고, 결과를 테두리·설정에 반영한다.
## 관련 SPEC
F-04 완료 기준 1, 2, 5, 3장(검정 40% 딤, 선택부 원본 밝기, 크기 라벨 `800 × 600`), F-05, F-06-1
## 범위
- App: `SelectionOverlayWindow : OverlayWindowBase`. 모든 모니터를 덮는 가상 화면 크기(음수 좌표, 멀티 모니터, Per-Monitor DPI 고려, 변환은 Core 유틸만 사용), 검정 40% 딤 + 선택부 투명(원본 밝기) + 크기 라벨, 크로스헤어 커서
- 선택 오버레이는 키 입력(Esc)을 받아야 하므로 포커스 처리 방식을 주의한다(NOACTIVATE 예외가 필요하면 `OverlayWindowBase`에 옵션으로 두고 보고서에 이유를 적는다. 캡처 제외는 반드시 유지)
- 드래그 → task-02의 정규화·최소 32px 판정 사용. 32px 미만이면 선택 취소(이전 영역 유지). Esc는 취소하고 이전 영역 유지. 확정되면 영역 상태를 갱신하고 task-04의 테두리 표시
- 영역 상태 서비스: 현재 영역, 변경 알림. `restoreLastRegion`이 켜져 있으면 영역 확정 시 설정에 저장(JSON 저장소 사용), 앱 시작 시 복원해 테두리 표시(task-02의 가상 화면 보정 사용)
- 트레이 메뉴 "영역 지정"을 연결(단축키는 task-07)
## 범위 밖
- 이동/리사이즈, 전역 단축키 등록, 스크린샷/녹화
## 완료 기준
1. [정적] `SelectionOverlayWindow`가 `OverlayWindowBase`를 상속하고 캡처 제외가 유지된다 (F-06-1)
2. [정적] 정규화·최소 크기 판정·좌표 변환이 Core 함수 호출로 이뤄지고 App에 계산 로직이 중복되지 않는다 (TECH-RULES App 로직 금지)
3. [정적] 확정 시 `restoreLastRegion` 조건으로 설정 저장, 시작 시 복원이 구현되어 있다(파일:줄) (F-04-5 연결). 예외는 로그를 남긴다
4. [자동] 영역 상태 서비스의 로직 중 Core로 뺄 수 있는 부분(예: 복원 여부 결정, 영역 교체/취소 규칙)에 xUnit 테스트가 있다. 이전 영역이 Esc/소형 드래그에서 유지되는 규칙 포함
5. [CI] windows-latest build/test 성공, 새 경고 없음
6. [수동] F-04-1 (딤·원본 밝기·크기 라벨), F-04-2 (Esc 취소 시 이전 영역 유지)는 Windows 확인 항목
## 검증 방법
qa가 코드 읽기 + 맥 build/test + CI 확인. 오버레이가 OverlayWindowBase를 우회하면 반려.
