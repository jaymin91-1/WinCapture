# task-03: Core 히트 테스트·이동/리사이즈·잠금·겹침 판정 (F-07, F-08 계산부)
## 목표
테두리 띠/그립 히트 테스트, 가상 화면 안 이동·리사이즈 제한, 녹화 중 잠금, 창-영역 겹침 판정을 Core 순수 함수로 구현한다.
## 관련 SPEC
F-07 완료 기준 1~4, F-08 완료 기준 1, TECH-RULES 2번
## 범위
- 히트 테스트: 결과 `Passthrough`(통과) / `Move`(이동) / `Resize`(리사이즈) / `Outside`(영역 밖). 띠는 영역 바깥 8px, 그립은 우하단 꼭짓점에서 오른쪽·아래 12px, 겹치면 그립 우선. 영역 내부는 통과
- 이동 계산: 시작 영역 + 드래그 델타 → 가상 화면 안으로 제한(음수 좌표 가상 화면 지원)
- 리사이즈 계산: 좌상단 고정, 최소 32×32, 가상 화면 경계에서 멈춤
- 잠금 상태 플래그가 켜지면 이동/리사이즈 결과가 원래 영역과 동일
- 사각형 겹침 판정(변만 맞닿으면 겹치지 않음)
- 드래그 중 툴팁 문자열 형식 `X, Y, W × H` 포맷 함수(문화권 독립)
## 범위 밖
- 실제 마우스 처리, 창, 커서(task-06)
## 완료 기준
1. [자동] 영역 (100,100,400,300): 점 (300,250)=통과, (95,200)=이동, (502,402)=리사이즈, (80,80)=영역 밖 (F-07-1)
2. [자동] 가상 화면 (-1920,0,3840,1080), 400×300 영역을 X=1700으로 → X=1520, Y=-50 → Y=0 (F-07-2)
3. [자동] 10×10으로 줄이면 32×32. 가상 화면 밖으로 늘리면 경계에서 멈춘다 (F-07-3)
4. [자동] 잠금 상태에서 이동/리사이즈 결과 = 원래 영역 (F-07-4)
5. [자동] 창 (0,0,500,500) vs 영역 (400,400,200,200) 겹침, 창 (0,0,300,300) 안 겹침, 창 (0,0,400,400) 안 겹침 (F-08-1)
6. [자동] 그립과 띠가 겹치는 점은 리사이즈로 판정되는 테스트가 있다
7. [정적] Core가 WPF/Win32/System.Drawing을 참조하지 않는다. task-02의 Rect 형식을 재사용한다
8. [CI] windows-latest build/test 성공
