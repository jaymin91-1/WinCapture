# task-03: App 호스트, Serilog, 트레이, 단일 인스턴스 (F-01)
## 목표
Generic Host 기반 DI와 Serilog 파일 로그, 트레이 아이콘과 메뉴 골격, 이름 있는 Mutex 단일 인스턴스, Per-Monitor V2 매니페스트를 App에 구현한다.
## 관련 SPEC
F-01 완료 기준 1~4, F-05 완료 기준 4, F-02 (App에서 설정 로드), SPEC 4장 트레이 메뉴 순서, 6장 로그
## 범위
- `App.xaml.cs`에서 Microsoft.Extensions.Hosting으로 DI 구성, Serilog 파일 싱크(`%LocalAppData%\WinCapture\logs`, 7일 보관), 설정 저장소 등록(경로 `%AppData%\WinCapture\settings.json`)
- 시작 시 설정 로드. 처리되지 않은 예외는 로그에 남긴다
- H.NotifyIcon.Wpf 트레이 아이콘 + 메뉴, 순서: 영역 지정 / 스크린샷 / 동영상 녹화 시작·정지 / GIF 녹화 시작·정지 / 창 표시·숨김 / 저장 폴더 열기 / 설정 / 종료. 설정과 종료만 동작, 나머지는 표시만 하고 비활성(IsEnabled=false). 트레이 아이콘은 새로 만든 중립적 아이콘(타 캡처 프로그램 로고 금지)
- 이름 있는 Mutex 단일 인스턴스. 두 번째 실행은 즉시 종료하되, 기존 인스턴스에 알려 설정 창을 앞으로 가져온다 (이름 있는 이벤트/파이프 등 간단한 신호 방식, 신호 수신부 로직은 App에 둔다)
- "종료" 메뉴로 트레이 아이콘을 정리하고 프로세스를 끝낸다. 트레이 상주 중 창이 없어도 종료되지 않는다(ShutdownMode)
- 앱 매니페스트에 Per-Monitor V2 DPI 인식 선언
- 메뉴의 "설정"은 task-04의 설정 창을 열 자리만 둔다 (task-04가 창을 연결). 이 작업에서는 최소한의 빈 Window로 대체해도 됨
## 범위 밖
- 설정 창 내용, 탭, WPF-UI 테마/Mica (task-04)
- 전역 단축키, 오버레이, 캡처 일체
- 비즈니스 로직을 App에 넣지 않는다
## 완료 기준
1. [정적] 단일 인스턴스가 이름 있는 Mutex로 구현되어 있다 (파일:줄을 리뷰에 기록)
2. [정적] 앱 매니페스트에 Per-Monitor V2 DPI 인식이 선언되고 csproj에 연결되어 있다
3. [정적] 트레이 메뉴 항목 순서가 SPEC 4장과 같고, 미구현 항목은 비활성이다. 설정/종료 메뉴에 핸들러가 연결되어 있다
4. [정적] Serilog 파일 싱크 경로가 `%LocalAppData%\WinCapture\logs`이고 7일 보관이다. DI에 설정 저장소가 등록되어 있다. 사용자명/개인 경로 하드코딩이 없다
5. [CI] 최신 커밋의 windows-latest build와 test가 성공하고 새 경고가 없다
6. [수동] 실행하면 트레이 아이콘이 나타나고 메뉴의 "종료"로 프로세스가 끝난다 (F-01 1)
7. [수동] 두 번째로 실행하면 새 인스턴스가 뜨지 않고 기존 인스턴스의 설정 창이 앞으로 나온다 (F-01 2)
## 검증 방법
qa가 코드를 읽어 [정적] 근거(파일:줄)를 기록하고, 맥 build/test와 CI를 직접 확인한다. [수동]은 Windows 확인 항목으로 넘긴다. 새로 추가한 NuGet 패키지가 SPEC 2장 범위 안인지 확인한다.
