# task-04: 설정 창 껍데기(WPF-UI, 탭 6개)와 README
## 목표
WPF-UI 기반 빈 설정 창(Mica, 좌측 내비게이션 탭 6개)을 만들어 트레이 "설정"과 두 번째 실행 신호에 연결하고, README 초안을 작성한다.
## 관련 SPEC
F-01 완료 기준 2 (설정 창 앞으로), SPEC 3장 디자인 원칙, 4장 설정 창 탭, F-14 완료 기준 1 (초안 수준)
## 범위
- WPF-UI(lepoco/wpfui) 적용: `FluentWindow` + Mica 배경, 시스템 라이트/다크 테마 추종, 좌측 NavigationView에 탭 6개 껍데기: 일반 / 단축키 / 캡처 / 녹화 / FFmpeg / 정보 (페이지 내용은 빈 안내 문구 정도)
- 설정 창은 닫기(X)를 눌러도 앱이 종료되지 않고 숨겨진다(또는 재사용 가능). 트레이 "설정" 클릭과 task-03의 두 번째 실행 신호 모두 이 창을 표시하고 앞으로 가져온다(최소화 상태면 복원)
- 시스템 폰트 사용, 별도 폰트 번들 금지
- 오버레이 아닌 일반 창이므로 `OverlayWindowBase`는 만들지 않는다 (세션 2)
- README 초안: 기능 소개, 빌드 방법, FFmpeg 별도 설치 안내(`winget install Gyan.FFmpeg` 또는 `scripts/get-ffmpeg.ps1`, FFmpeg 라이선스는 FFmpeg 측 귀속), 기본 단축키 표(F-03 표), 라이선스(MIT)
## 범위 밖
- 각 탭의 실제 설정 UI, ViewModel 로직, 단축키 편집 (세션 6)
- `scripts/get-ffmpeg.ps1` 실제 구현, 릴리스 워크플로, 첫 실행 안내 화면
- 앱 창 숨김/표시 단축키 (세션 2)
## 완료 기준
1. [정적] 설정 창이 WPF-UI `FluentWindow`이며 Mica 배경과 시스템 테마 추종이 설정되어 있고, 탭 6개(일반/단축키/캡처/녹화/FFmpeg/정보)가 SPEC 4장 순서로 있다 (파일:줄 기록)
2. [정적] 창 닫기가 앱 종료로 이어지지 않으며, 트레이 "설정"과 두 번째 실행 신호가 같은 창 표시 경로를 쓴다
3. [정적] README에 기능 소개, 빌드 방법, `winget install Gyan.FFmpeg` 안내, 기본 단축키 표 7개가 SPEC과 일치하게, 라이선스 항목이 있다
4. [정적] 번들 폰트, 타 캡처 프로그램 이름/로고 사용이 없다. 비밀값/개인 경로 없음
5. [CI] 최신 커밋의 windows-latest build와 test가 성공하고 새 경고가 없다. 앞 작업의 테스트가 그대로 통과한다
6. [수동] 설정 창이 Mica 배경으로 뜨고 시스템 테마를 다크로 바꾸면 다크로 바뀐다 (세션 확인 항목)
7. [수동] 트레이 "설정"으로 창이 열리고, X로 닫아도 트레이 아이콘은 남는다
## 검증 방법
qa가 XAML과 코드를 읽어 [정적] 근거를 기록하고, 맥 build/test와 CI를 확인한다. [수동]은 Windows 확인 항목으로 넘긴다.
