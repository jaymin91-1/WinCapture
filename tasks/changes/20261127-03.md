# change-20261127-03: 설정 창 열기 예외 수정과 트레이 우클릭 즉시 메뉴
## 목표
트레이 "설정"/"창 표시·숨김"에서 설정 창을 만들 때 나는 예외(SettingsWindow.xaml 26행·38행 부근 NavigationViewItem.Icon, ArgumentException, Viewbox 관련)를 고치고, 트레이 아이콘 우클릭 메뉴가 즉시 뜨게 한다.

## 관련 SPEC
- SPEC 4장 "트레이 아이콘 클릭 반응" (커밋 780b60a), 3장 설정 창 탭 아이콘 규칙
- 직전 수정 20261127-02 (탭 아이콘을 Path/geometry 리소스로 교체)

## 범위
- 원인 확정과 수정(설정 창 예외). 사용자 보고상 NavigationViewItem.Icon에 Viewbox를 넣은 것이 의심된다(Wpf.Ui의 NavigationViewItem.Icon은 IconElement 타입이어야 하는데 Viewbox는 IconElement가 아님). 원인 확정은 coder가 하며, 같은 Visual 인스턴스를 여러 부모에 넣는 경우 등 다른 가능성도 확인한다. 탭 6개 모두 같은 방식이면 6개 모두 고친다. 외형은 20261127-02 결과(얇은 선 아이콘, Foreground 상속, 18px)를 유지한다. (예: IconElement 파생 래퍼를 쓰거나 Wpf.Ui가 허용하는 방식으로 Path geometry를 담는다. 새 패키지는 금지)
- 재발 방지: 설정 창을 비롯한 App의 모든 XAML에서 같은 패턴(Icon 속성에 IconElement가 아닌 요소)이 없음을 grep으로 확인하고, 명령과 결과를 보고서에 적는다.
- 가능하면 맥에서 검증 가능한 안전장치를 둔다. 예: XAML 파일의 `NavigationViewItem.Icon` 안 요소가 허용 타입인지 검사하는 xUnit 테스트(문자열/XML 파싱, WPF 참조 없이 가능한 범위, Core.Tests가 App 파일을 읽는 방식이 TECH-RULES에 어긋나면 하지 말고 보고서에 이유를 적는다). 불가능하면 정적 근거(파일:줄)로 대체한다.
- 트레이 아이콘 우클릭 메뉴가 즉시 뜨도록 수정. 지연의 원인(예: 메뉴 열기 전 무거운 작업, 메뉴 구성/핸들러, H.NotifyIcon의 ContextMenuMode 또는 PopupActivation/메뉴 종류 설정, 메뉴를 열 때마다 새로 생성)을 코드로 확인하고 설명한 뒤 고친다.
- 트레이 아이콘 왼쪽 클릭: 컨트롤 바는 change 20261127-04에서 만든다. 이번 작업에서는 왼쪽 클릭 시 설정 창을 보이고 앞으로 가져오게 임시로 둔다(예외 없이 동작해야 함). 04에서 컨트롤 바 표시로 바꾼다. 코드 주석이나 보고서에 이 임시 동작임을 명시한다.
- 설정 창이 열릴 때 예외가 나도 앱 전체가 죽지 않는지 확인한다(이미 처리되어 있다면 현황만 보고서에 적는다. 새 로깅 체계는 만들지 않는다).

## 범위 밖
- 작업표시줄 아이콘, 컨트롤 바, captureMode (20261127-04)
- 트레이 메뉴 항목 구성/순서 변경, 설정 창 탭 개수·순서·페이지 변경
- 새 NuGet 패키지, SPEC/TECH-RULES/SESSIONS 수정

## 완료 기준
1. [CI] 솔루션 build와 test가 windows-latest에서 성공하고, 맥 `dotnet test tests/WinCapture.Core.Tests`가 기존 테스트 삭제·skip 없이 통과한다.
2. [정적] 보고서에 예외 원인이 코드(파일:줄)와 Wpf.Ui 타입 제약 근거로 설명되어 있고, 수정 후 SettingsWindow.xaml의 6개 탭 Icon이 해당 속성이 요구하는 타입(IconElement 계열 등)만 담는다. (파일:줄 기록)
3. [정적] 수정 후에도 탭 아이콘 6개가 Path geometry 선 아이콘(Fill 없음, round cap/join, Foreground 상속, 18px)이며 geometry 데이터가 변경 전과 같다. 탭 개수·순서·페이지 연결이 그대로다. (git diff로 확인)
4. [정적] 같은 패턴이 다른 곳에 없음을 보여 주는 grep 명령과 결과가 보고서에 있고, QA가 같은 grep을 재실행해 일치한다.
5. [자동] (가능한 경우) 탭 Icon 허용 타입 검사 테스트가 존재하고 수정 전 패턴에서는 실패, 수정 후 통과한다. 불가능하면 보고서에 사유를 적고 기준 2·4로 대체한다.
6. [정적] 트레이 우클릭 지연 원인이 코드로 설명되어 있고, 수정이 메뉴 열기 경로에서 지연 요인을 제거했다. (파일:줄 기록) 트레이 메뉴 항목 순서와 동작은 변경 전과 같다.
7. [정적] 트레이 왼쪽 클릭이 설정 창을 보이고 앞으로 가져오는 임시 동작이며, 04에서 컨트롤 바로 바꾼다는 주석 또는 보고서 명시가 있다.
8. [정적] 새 NuGet 패키지 없음, Core에 WPF 참조 없음, 바이너리/빌드 산출물 미커밋.
9. [수동] Windows에서 트레이 "설정"과 "창 표시/숨김"을 눌러 설정 창이 예외 없이 열리고, 탭 6개의 아이콘이 이전(20261127-02)과 같게 보인다.
10. [수동] 트레이 아이콘을 오른쪽 클릭하면 메뉴가 체감 지연 없이 즉시 뜬다. 왼쪽 클릭하면 설정 창이 열린다(임시 동작).
