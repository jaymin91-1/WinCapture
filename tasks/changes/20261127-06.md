# change-20261127-06: 컨트롤 바 v2(메뉴바·상태 카드·단축키 팝업), 라이트 고정, 작업표시줄 아이콘
## 목표
승인된 목업 v2에 맞춰 컨트롤 바를 다시 만들고, 단축키 팝업을 추가하고, 테마를 라이트 고정으로 바꾸고, 작업표시줄에 앱 아이콘이 나타나지 않는 원인을 규명해 고친다. 20261127-05(영역 상태 이벤트·`Clear()`, 모니터 대체 규칙)가 통과한 뒤 그 위에서 작업한다.

## 관련 SPEC
- 3장 디자인 원칙(라이트 기본, 시스템 다크 비추종), 4장 "컨트롤 바", "단축키 팝업", "앱 아이콘", "영역 상태", F-03 표, 7장 `captureMode`
- 목업(승인): docs/design/mockup/controlbar-light.png, controlbar-dark.png, hotkey-popup-light.png
- 이전 작업: 20261127-04(1차 구현, 작업표시줄 아이콘 미표시), 20261127-05(영역 상태)

## 범위
1. 컨트롤 바 v2 (위→아래, 약 320×290 DIP 고정)
   1. 메뉴바: [설정] [단축키] [창 숨기기]. 설정=설정 창 열기, 단축키=단축키 팝업 열기, 창 숨기기=창 표시·숨김 단일 경로.
   2. 상태 카드: 영역 상태(`지정 영역`/`전체 화면`) + 좌표 `X, Y, W × H`(물리 픽셀, 전체 화면이면 ` · 모니터 N` 추가) + 오른쪽 칩(`테두리 표시 중`/`테두리 숨김`/`테두리 없음`). 05의 영역 상태 변경 이벤트로 즉시 갱신. 문자열 생성은 Core 순수 함수.
   3. 모드 선택: [사진] [동영상] [GIF] 단일 선택(captureMode 저장·복원 유지).
   4. 버튼: [영역 지정] [영역 해제] 한 줄, 그 아래 큰 강조색 [캡처]. [영역 해제]는 05의 `Clear()`(ClearRegion 단축키와 같은 경로). 캡처 버튼 문구는 모드·녹화 상태에 따라 `스크린샷 찍기` / `녹화 시작`·`녹화 정지` / `GIF 녹화 시작`·`GIF 녹화 정지`. 미구현 모드는 비활성+`… 준비 중` 툴팁(04 동작 유지). 문구 생성은 Core 순수 함수.
   5. 본문에 설정·창 숨기기 버튼과 단축키 목록을 두지 않는다.
   6. 리사이즈·최대화 불가(`ResizeMode=CanMinimize` 또는 `NoResize`, 최대화 버튼 없음), 내용이 잘리지 않는 고정 크기(SizeToContent 후 고정 권장). 기존 동작(X=숨김, 시작 시 표시, ShowInTaskbar=true, 트레이 왼쪽 클릭, 창 표시·숨김 단일 경로, autoHideAppWindow)은 유지. `OverlayWindowBase`를 상속하지 않는다.
2. 단축키 팝업(새 창, 읽기 전용)
   - 약 400 DIP 폭, 리사이즈 없음, 컨트롤 바 위에 뜸(Owner 지정). 제목 `단축키`, 설명 `현재 설정된 전역 단축키입니다.`
   - F-03 표의 7개 동작과 현재 설정된 조합을 키캡 모양으로 나열. 등록 실패 조합은 빨간 테두리 + `사용 중인 조합`.
   - 하단 `변경은 설정 › 단축키 탭에서 합니다.`, 버튼 [설정 열기](설정 창을 열고 단축키 탭 선택) [닫기].
   - 행 데이터(동작 이름, 키캡 토큰 목록, 미설정 표기, 등록 실패 여부 → 표시 정보)는 Core 순수 함수. 팝업은 열 때 현재 설정·등록 결과를 읽는다(편집 기능 없음).
   - 설정 창에 단축키 탭이 아직 없으면 설정 창을 열고 가능한 가장 가까운 탭(없으면 첫 탭)을 선택하는 진입점(`OpenSettings(tab)` 등)만 만들고 보고서에 적는다.
3. 테마 라이트 고정
   - `SystemThemeWatcher.Watch`(컨트롤 바·설정 창), `ApplicationThemeManager.Changed` 구독, `ApplySystemTheme`로 시스템 테마를 따르는 코드를 제거하고 라이트로 고정한다(WPF-UI 테마·앱 팔레트 모두 Light, 강조색은 앱 파랑). 다크 리소스 파일은 남겨도 된다.
   - README의 "시스템 라이트/다크 테마 추종" 문구를 "라이트 테마" 취지로 갱신한다.
4. 작업표시줄 아이콘 미표시 원인 규명과 수정(기존 항목 유지)
   - 04에서 exe `ApplicationIcon`, 창 `Icon`을 지정했는데도 작업표시줄에 아이콘이 안 보였다. 추측하지 말고 코드·빌드 설정에서 원인을 찾아 보고서에 "원인"으로 적는다. 최소한 확인: (a) .ico 빌드 액션과 `Window.Icon` pack URI, (b) WPF-UI `FluentWindow`/`TitleBar` 계열이면 `Window.Icon`만으로 되는지, `TitleBar.Icon`/`WM_SETICON`(ICON_BIG/ICON_SMALL) 필요 여부, (c) `ShowInTaskbar`·창 스타일(WS_EX_TOOLWINDOW 등), (d) .ico가 유효한 다중 크기 ICO인지(헤더 덤프, 16/24/32/48/256 포함), (e) 아이콘 로딩 예외 삼킴 여부, (f) exe 임베드 아이콘(csproj `ApplicationIcon` 경로).
   - 맥에서 확인 가능한 정적 근거(파일:줄, ICO 헤더 덤프, 산출물 리소스 확인)를 보고서에 붙인다. 원인이 여러 개면 모두 수정. 새 NuGet 금지. .ico 재생성(생성 스크립트 갱신, 원본 직접 생성 유지) 허용.
   - 안전장치로 컨트롤 바·설정 창이 SourceInitialized에서 코드로 아이콘 명시 설정(`BitmapFrame.Create(pack URI)`, 필요 시 WM_SETICON). 실패 시 로그.
5. 기존 오버레이 창은 변경하지 않는다.

## 완료 기준
1. [CI] 솔루션 build와 test가 windows-latest에서 성공하고, 맥 `dotnet test tests/WinCapture.Core.Tests`와 `dotnet build WinCapture.sln`이 통과한다. 기존 테스트 삭제·skip·기대값 변경 없음, 새 경고 없음.
2. [자동] 상태 카드 문자열 순수 함수 테스트
   - 지정 영역 (100,100,400,300) → `지정 영역`, `100, 100, 400 × 300`.
   - 전체 화면 (0,0,1920,1080), 모니터 번호 1 → `전체 화면`, `0, 0, 1920 × 1080 · 모니터 1`. 지정 영역에는 `· 모니터`가 붙지 않는다.
   - 음수 좌표 (-1920,0,1920,1080) → `-1920, 0, 1920 × 1080`.
3. [자동] 테두리 칩 순수 함수 테스트: 지정 영역+표시 → `테두리 표시 중`, 지정 영역+숨김 → `테두리 숨김`, 전체 화면 → `테두리 없음`(숨김 여부 무관).
4. [자동] 캡처 버튼 문구 순수 함수 테스트: Screenshot → `스크린샷 찍기`; Video → `녹화 시작`, 녹화 중 `녹화 정지`; Gif → `GIF 녹화 시작`, 녹화 중 `GIF 녹화 정지`.
5. [자동] 단축키 팝업 행 데이터 순수 함수 테스트: 기본 설정에서 F-03 표 순서의 7행이 나오고 SelectRegion 행 키캡이 `Ctrl`,`Alt`,`R`, Screenshot이 `Ctrl`,`Alt`,`S`이다. 설정의 조합을 바꾸면 해당 행만 바뀐다. 등록 실패 집합에 든 동작은 실패 표시 플래그가 true이고 나머지는 false. 빈 문자열/미설정은 일관된 표기(`없음`)이며 규칙을 보고서에 명시한다.
6. [정적] 컨트롤 바 XAML이 메뉴바 → 상태 카드 → 모드 3개 → [영역 지정][영역 해제] → 큰 [캡처] 순서로 위→아래 배치되고, 본문에 설정·창 숨기기 버튼과 단축키 목록이 없다. 메뉴 항목이 [설정][단축키][창 숨기기] 순서다. (파일:줄 기록)
7. [정적] 크기 고정·리사이즈 불가·최대화 불가가 XAML/코드로 설정되어 있다. X=Hide, 시작 시 표시, ShowInTaskbar=true 유지. 컨트롤 바·단축키 팝업이 `OverlayWindowBase`를 상속하지 않는다. (파일:줄 기록)
8. [정적] 상태 카드가 05의 영역 상태 변경 이벤트를 구독해 갱신하고 창 닫힘 시 구독이 해제된다(또는 수명이 앱과 같음을 보고서에 명시). [영역 해제]가 `Clear()`를 호출한다. 메뉴 [창 숨기기]가 기존 창 표시·숨김 단일 경로를 쓴다. (파일:줄 기록)
9. [정적] 단축키 팝업: 읽기 전용(편집 컨트롤 없음), 7행 데이터를 위 Core 함수에서 가져오고, 실패 조합에 빨간 테두리와 `사용 중인 조합`을 표시하며, [설정 열기]가 설정 창(단축키 탭 또는 보고서에 명시한 대체)을 열고 [닫기]가 팝업을 닫는다. 문구가 SPEC과 일치한다. (파일:줄 기록)
10. [정적] 라이트 고정: `SystemThemeWatcher`, `ApplicationThemeManager.Changed`, `ApplySystemTheme` 등 시스템 테마 추종 코드가 없고 시작 시 Light가 적용된다. README의 시스템 테마 추종 문구가 갱신되었다. (grep 결과·파일:줄 기록)
11. [정적] 작업표시줄 아이콘 미표시의 **원인**이 보고서에 코드 근거와 함께 적혀 있고, 대응하는 수정이 코드에 있다. (a)~(f)별 결과가 보고서에 있다. ICO가 유효한 다중 크기이며 작업표시줄용 크기를 포함한다는 근거(헤더 덤프)가 있다. 컨트롤 바·설정 창·exe 모두 아이콘이 지정되어 있다. (파일:줄 기록)
12. [정적] 새 NuGet 없음, Core에 WPF 참조 없음, `WH_KEYBOARD_LL` 미사용, 빌드 산출물·비밀 값 미커밋. 기존 오버레이 창은 모두 `OverlayWindowBase`를 상속한다. 이전 동작(창 표시·숨김 단일 경로, 트레이 왼쪽 클릭, autoHide, 모드 저장·복원)의 코드가 유지된다.

14. [수동] 컨트롤 바가 목업 controlbar-light.png와 같은 구성(메뉴바/상태 카드/모드/버튼/큰 캡처)으로 보이고, 약 320×290로 작고, 가장자리를 끌어도 크기가 바뀌지 않으며 최대화가 되지 않는다. 100%/150% 배율에서 잘리지 않는다. Windows를 다크 모드로 두어도 앱은 라이트로 보인다.
