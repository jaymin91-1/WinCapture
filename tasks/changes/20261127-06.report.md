## 작업표시줄 아이콘 원인 규명
- (a) .ico 빌드 액션·pack URI: csproj 14 `<Resource Include="Assets\AppIcon.ico" />`, XAML `Icon="pack://application:,,,/Assets/AppIcon.ico"`. 산출물 `obj/.../WinCapture.App.g.resources`에 `assets/appicon.ico`, baml 포함 확인. 정상 -> 원인 아님.
- (b) FluentWindow: **가장 유력한 원인**. WPF-UI 4.3.0 Wpf.Ui.dll 메타데이터에 `WM_SETICON`, `RemoveWindowTitlebarContents`, `WTNCA_NODRAWICON`이 존재(`strings`로 확인, 디컴파일은 못 함). 즉 WPF-UI가 FluentWindow/백드롭 처리(SystemThemeWatcher·ExtendsContentIntoTitleBar 경로)에서 창에 WM_SETICON(빈 아이콘)을 보내 WPF가 `Window.Icon`으로 설정한 HICON을 지울 수 있다. TitleBar.Icon은 제목줄 그림일 뿐 작업표시줄 HICON이 아니다. 04는 `Window.Icon`만 지정했고 WM_SETICON 재설정이 없었다. 맥에서 동작 확인 불가 -> 추정(확정 아님).
  - 수정: `AppWindowIcon.Attach`(AppWindowIcon.cs)가 SourceInitialized·Loaded·ContentRendered 3시점에 `WindowIcon.Apply`(Native/Interop/WindowIcon.cs)로 `WM_SETICON`(ICON_SMALL/ICON_BIG, DPI별 SM_CXSMICON/SM_CXICON 크기 프레임)을 다시 설정. WPF-UI 처리 뒤에 다시 설정되도록 여러 시점. Closed에서 HICON 해제. 컨트롤 바·설정 창·팝업에 적용. 더불어 `Window.Icon = BitmapFrame.Create(pack URI)`를 코드로도 설정.
- (c) ShowInTaskbar·창 스타일: ControlBarWindow.xaml:10 `ShowInTaskbar=True`, 컨트롤 바는 OverlayWindowBase가 아니므로 WS_EX_TOOLWINDOW/NOACTIVATE 미적용(코드 grep: AddExtendedStyles는 Overlay/OverlayWindowBase.cs에서만). 원인 아님.
- (d) ICO 유효성: 기존 파일은 7프레임(16/24/32/48/64/128/256) 모두 PNG 압축이었다(헤더: 개수 7, 각 엔트리 planes=1 bpp=32, 오프셋 118부터). 헤더는 유효하나 작은 프레임까지 PNG 압축은 비관례적이라 로더·WPF 호환 위험이 있어, 생성 스크립트(scripts/generate-app-icon.py)를 고쳐 16~128은 클래식 DIB(BITMAPINFOHEADER+BGRA+AND 마스크), 256은 PNG로 재생성. 새 헤더 덤프: `16 16 planes1 bpp32 len1128 off118 / 24 24 .. 2440 / 32 32 .. 4264 / 48 48 .. 9640 / 64 .. 16936 / 128 .. 67624 / 256(0) .. 2235 off102150 PNG`, 총 104385 바이트. 테스트 `IcoFileTests`가 16/24/32/48/256 포함·32bpp·DIB/PNG 구분을 검증.
- (e) 예외 삼킴: 04의 로딩은 XAML 선언뿐이라 실패 시 예외가 났을 것(창이 떴으므로 로딩 자체는 성공). 새 코드는 실패를 삼키지 않고 Serilog 경고로 남긴다(AppWindowIcon.cs, 단계·창 이름 포함).
- (f) exe 임베드: csproj 10 `<ApplicationIcon>Assets\AppIcon.ico</ApplicationIcon>`(경로 정상, 파일 존재). 맥 산출물은 Mach-O apphost라 PE 리소스를 볼 수 없음(Windows 확인 필요). 새 ICO(DIB 프레임)가 exe 아이콘에도 더 안전.
- 결론: 확정 불가이므로 (b) 유력 원인 + (d) 보조 위험을 모두 방어적으로 처리. 로그(%LocalAppData%\WinCapture\logs)에 `Setting the window icon` 경고가 없으면 WM_SETICON이 성공한 것.

## 내린 판단과 이유
- 상태 카드 점: 지정 영역은 빨강(WarningBrush), 전체 화면은 회색. 목업에는 빨간 점만 있어 전체 화면 색은 임의(회색) 선택.

- 메뉴바는 `Menu` 드롭다운이 아니라 클릭형 플랫 버튼(SPEC의 메뉴 항목 3개가 바로 동작).
- 팝업은 컨트롤 바가 보일 때만 Owner 지정. 컨트롤 바 숨김 시 Owner가 숨겨지면 팝업도 함께 숨는다.
- 녹화 상태 표시용 `SetRecording(bool)`만 준비(녹화는 범위 밖).
- 다크 리소스(Colors.Dark.xaml)는 남김.
