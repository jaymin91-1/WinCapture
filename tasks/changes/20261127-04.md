# change-20261127-04: 앱 아이콘과 컨트롤 바
## 목표
작업표시줄/exe/창에 캡처를 연상시키는 원본 앱 아이콘을 넣고, SPEC 4장 "컨트롤 바"를 구현한다. 20261127-03(통과)이 끝난 뒤에 진행한다.

## 관련 SPEC
- SPEC 4장 "컨트롤 바", "앱 아이콘", "트레이 아이콘 클릭 반응" (커밋 780b60a), 3장 팔레트(`#2F7CF6`)와 오버레이 규칙, 7장 `captureMode`(`Screenshot` | `Video` | `Gif`, 기본 `Screenshot`)
- TECH-RULES.md (Core는 WPF 비참조, 새 패키지 금지)

## 범위
1. 앱 아이콘
   - 파랑 `#2F7CF6` 계열, 트레이 아이콘과 같은 디자인 계열의 캡처를 연상시키는 원본 디자인(예: 둥근 사각형 + 모서리 괄호/원). 다른 캡처 프로그램의 로고·아이콘을 닮게 하지 않는다.
   - exe에 `ApplicationIcon` 지정, 컨트롤 바와 설정 창에 `Icon` 지정. 작업표시줄에 아이콘이 표시되게 한다.
   - 바이너리 .ico를 저장소에 추가하는 것을 이번에 한해 허용한다. 단 coder가 직접 생성한 원본이어야 하며(스크립트 생성 가능, 외부 이미지·아이콘 복사 금지), 생성 방법과 "앱이 직접 만든 원본임"을 보고서에 명시한다. 생성 스크립트가 있다면 함께 커밋해 재현 가능하게 한다. 여러 크기(16/32/48/256 등)를 포함한다.
2. Core: `captureMode` 설정 키
   - Core의 설정 모델에 `captureMode`(열거형 Screenshot/Video/Gif, JSON 문자열 직렬화, 기본 Screenshot) 추가. 알 수 없는 값/누락 시 기본값으로 복원한다(기존 설정 파일 로딩 규칙과 동일하게).
3. 컨트롤 바 창 (App)
   - 작은 일반 창. 버튼 [영역 지정] [캡처] [설정] [창 표시·숨김], 모드 선택 [사진] [동영상] [GIF](셋 중 하나만, 기본 사진). 크기는 작게(버튼 한 줄 + 모드 한 줄 수준), 3장 팔레트와 20261127-01 스타일 리소스(라이트/다크) 사용.
   - 컨트롤 바는 앱 일반 창이며 오버레이 창이 아니다. 따라서 `OverlayWindowBase` 상속 대상이 아니고 캡처 제외·작업표시줄 미노출 규칙의 대상이 아니다. 작업표시줄에 표시된다(ShowInTaskbar=true). 기존 오버레이 창은 변경하지 않는다.
   - 시작 시 표시한다. 닫기(X)는 종료가 아니라 숨김이다(종료는 트레이 "종료"). 이미 `ShutdownMode`나 닫기 처리가 있으면 그와 충돌하지 않게 한다.
   - [영역 지정]은 기존 영역 지정 동작(트레이 메뉴 "영역 지정"과 같은 경로), [설정]은 설정 창 열기.
   - [캡처]는 선택한 모드의 동작을 실행한다. Screenshot은 기존 스크린샷 동작(트레이 "스크린샷"과 같은 경로). 구현되지 않은 모드(현 시점의 Video, Gif 중 아직 없는 것)는 [캡처]를 비활성으로 하고 툴팁으로 "아직 구현되지 않았다"는 안내를 한다. 현재 구현 상태를 확인해 어떤 모드가 구현되었는지 보고서에 적는다.
   - 모드 선택은 `captureMode`에 저장하고 다음 실행 때 복원한다.
   - 자동 숨김(`autoHideAppWindow`)은 컨트롤 바에도 적용한다(기존 설정 창에 적용된 방식과 같은 규칙).
4. 창 표시·숨김
   - [창 표시·숨김] 버튼, 단축키, 트레이 메뉴가 같은 하나의 경로를 쓰며, 설정 창과 컨트롤 바를 함께 숨기고 다시 보인다. 트레이 아이콘과 테두리는 그대로 둔다.
5. 트레이 왼쪽 클릭
   - 컨트롤 바를 보이고 앞으로 가져온다(03의 임시 동작인 설정 창 표시를 대체). 숨겨졌거나 최소화된 상태에서도 복원한다. 우클릭 즉시 메뉴(03)는 유지한다.

## 범위 밖
- 동영상/GIF 녹화 기능 자체의 구현(해당 세션 작업), 모드 선택 UI만 만든다
- 트레이 메뉴 항목 구성 변경, SPEC/TECH-RULES/SESSIONS 수정, 새 NuGet 패키지
- 설정 창 탭 구성 변경

## 완료 기준
1. [CI] 솔루션 build와 test가 windows-latest에서 성공하고, 맥 `dotnet test tests/WinCapture.Core.Tests`가 기존 테스트 삭제·skip 없이 통과한다.
2. [자동] captureMode 기본값이 `Screenshot`이고, 설정 JSON 저장 후 로드 시 `Video`/`Gif` 값이 유지되며, JSON에는 문자열("Screenshot"/"Video"/"Gif")로 기록된다. 알 수 없는 문자열이나 키 누락 시 `Screenshot`으로 복원된다. 대응 xUnit 테스트가 있다.
3. [정적] exe `ApplicationIcon`, 컨트롤 바·설정 창 `Icon`이 지정되었다(csproj/XAML 파일:줄). .ico는 여러 크기를 포함하고, 보고서에 앱이 직접 만든 원본임과 생성 방법이 적혀 있다. 외부 이미지 복사 흔적이 없다.
4. [정적] 컨트롤 바에 버튼 4개와 모드 3개(단일 선택, 기본 사진)가 있고 SPEC 4장 구성과 일치한다. ShowInTaskbar가 true이고 OverlayWindowBase를 상속하지 않으며 보고서에 그 이유가 적혀 있다. 기존 오버레이 창은 모두 여전히 OverlayWindowBase를 상속한다. (파일:줄 기록)
5. [정적] 모드 선택이 captureMode에 저장·복원된다. 구현되지 않은 모드에서 [캡처]가 비활성이고 툴팁이 있다. Screenshot에서는 기존 스크린샷 경로를 호출한다. (파일:줄 기록)
6. [정적] 닫기(X)가 Hide로 처리되고 앱이 종료되지 않는다. 종료는 트레이 "종료"뿐이다. 시작 시 컨트롤 바가 표시된다. (파일:줄 기록)
7. [정적] 창 표시·숨김이 버튼/단축키/트레이 모두 하나의 경로이고 설정 창과 컨트롤 바를 함께 처리한다. 트레이 아이콘/테두리는 영향받지 않는다. autoHideAppWindow가 컨트롤 바에도 적용된다. (파일:줄 기록)
8. [정적] 트레이 왼쪽 클릭이 컨트롤 바를 보이고 앞으로 가져온다. 우클릭 즉시 메뉴 수정(03)이 유지된다. 트레이 메뉴 항목 순서는 변경 전과 같다. (파일:줄 기록)
9. [정적] 새 NuGet 패키지 없음, Core에 WPF 참조 없음, `WH_KEYBOARD_LL` 미사용, 빌드 산출물·비밀 값 미커밋. 바이너리는 앱 아이콘 .ico 외에 없다.
10. [수동] Windows 작업표시줄에 앱 아이콘이 나타나고, exe 파일과 설정 창·컨트롤 바 제목줄에도 같은 아이콘이 보인다.
11. [수동] 앱 시작 시 컨트롤 바가 뜨고, 버튼 4개와 사진/동영상/GIF 모드 선택이 보이며 스타일이 라이트/다크 설정을 따른다. 모드를 바꾸고 앱을 재시작하면 선택이 유지된다.
12. [수동] [영역 지정], [설정], [캡처](사진 모드)가 동작한다. 미구현 모드에서는 [캡처]가 비활성이고 툴팁이 보인다.
13. [수동] [창 표시·숨김]과 단축키, 트레이 메뉴로 설정 창과 컨트롤 바가 함께 숨겨지고 다시 보인다(트레이 아이콘은 유지). 컨트롤 바 X는 숨김만 하고 앱은 계속 실행된다. 트레이 왼쪽 클릭이 컨트롤 바를 앞으로 가져온다. 트레이 "종료"로 종료된다.
