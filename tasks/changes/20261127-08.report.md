## 원인 (후보 a~d)
WPF-UI 4.3.0. 이 맥에는 디컴파일러가 없어 WPF-UI 내부 동작은 소스·디컴파일로 확인하지 못했다(기억/공개 소스 기반). 그 부분은 "미확인"으로 표시한다.
- a) 고정 폭 320: **확정(폭 과다의 직접 원인)**. 07의 `<Grid Width="320">`(`ControlBarWindow.xaml` 구 17행)이 버튼 고유 폭과 무관하게 창을 320으로 만들고, 본문 `Margin=12`라 버튼은 296이었다. 제거했다.
- b) 보이지 않는 리사이즈/확장 프레임: **미확인(코드로 기각 근거는 있음)**. 07에서 `WS_THICKFRAME` 제거 + `ResizeBorderThickness=0`이므로 창 사각형에 프레임이 남을 이유는 없다. 다만 스타일 변경 후 `SWP_FRAMECHANGED`가 없어 비클라이언트 영역이 즉시 재계산되지 않았을 수 있었다(07의 누락) → 이번에 추가. Windows에서 확정할 수 없어 `FixedSizeWindow.LogBounds`가 `GetWindowRect`, `DWMWA_EXTENDED_FRAME_BOUNDS`, ActualWidth/Height, dpi를 로그에 한 번 남긴다(`%LocalAppData%\WinCapture\logs`). 두 값이 다르면 보이지 않는 프레임이 있다는 뜻이다. DWM 그림자는 창 사각형 바깥이라 폭에 영향이 없다. 보정(SetWindowPos 축소)은 로그 근거 없이 넣으면 위험하므로 넣지 않았다.
- c) NCHITTEST 훅 순서/`ResizeBorderThickness` 덮어쓰기: **미확인, 07의 구조적 약점은 확정**. 07 훅은 `HwndSource.AddHook`(나중에 추가된 훅이 먼저 호출됨)에 의존했고, WPF-UI TitleBar/WindowChrome이 훅 이후나 스타일 재적용 시 sizing 코드를 다시 돌려줄 수 있는지 막을 수 없었다. WM_SETCURSOR 차단도 없었다. 이번에는 훅 순서와 무관하게 **체인 최종 결과**를 보는 서브클래스로 바꿨다(아래 경로).
- d) FluentWindow/TitleBar 최소 폭: **미확인(영향 낮다고 판단)**. 타이틀바는 아이콘+제목+최소화+닫기(46px×2 가량)로 약 200 DIP대이고 본문 열(296+16=312)보다 좁아 폭을 결정하지 않는다. 폭 기준은 캡처 버튼 열이다. Windows 로그의 Actual 폭이 312와 같은지로 확인된다.
- 07이 효과 없었던 이유(추정 포함): 폭은 a 때문, 포인터는 c의 약점(훅 순서 의존, WM_SETCURSOR 미처리, FRAMECHANGED 누락). 포인터 잔존의 정확한 한 가지 원인은 맥에서 확정할 수 없어 3중으로 막았다.

## 폭 계산 (DIP)
- 캡처 버튼 열: `MinWidth=296`(= 구 목업 본문 폭 320-24. 상태 카드의 칩과 좌표 문구가 이전과 동일하게 들어가는 폭) vs 가장 긴 문구 `GIF 녹화 시작` 자연 폭(약 150): MinWidth가 지배 → 296.
- 창 보이는 폭 = 296 + 8 + 8 = **312**. 높이 = 타이틀바 + 메뉴바 + (8 + 내용 + 8).
- 모든 문구 전환 시 폭 일정: 숨은 sizer가 5개 문구를 모두 잰다. 고정 창 폭은 없다(버튼의 MinWidth만 있음).
- 선택 근거: 상태 카드는 좌표 문구가 길면(`0, 0, 2560 × 1440 · 모니터 1`) 칩 때문에 버튼 자연 폭(~150)에는 들어가지 않는다. SPEC이 "카드가 같은 열 안에 들어가야 한다"고 하므로 버튼 MinWidth를 올렸다. 296보다 좁히면 카드가 더 잘린다.

## 포인터 차단 경로 (후보 c 포함)

2. `WS_THICKFRAME|WS_MAXIMIZEBOX` 제거 + 이제 `SWP_FRAMECHANGED` 적용(`WindowInterop.RemoveSizingStyles`).

WM_NCHITTEST를 기본 체인(WPF 훅, WindowChrome, WPF-UI)에 먼저 통과시킨 뒤 결과가 sizing 코드(HTLEFT..HTBOTTOMRIGHT, HTSIZE, HTMAXBUTTON)면 HTCLIENT로 교체. 훅 등록 순서와 무관. WM_NCDESTROY/Closed에서 해제. `FixedSizeWindow.Attach`에서 SourceInitialized에 설치(컨트롤 바·단축키 팝업 모두).
5. 유지: SC_SIZE/SC_MAXIMIZE 차단, 시스템 메뉴 항목 삭제, 캡션 더블클릭 차단, GETMINMAXINFO 고정, 최대화 상태 복귀. 최소화·X(숨김)·이동은 그대로.
